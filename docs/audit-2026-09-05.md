# Configuration audit — 2026-09-05

The host/common/role architecture is sound. The main maintenance burden was large
application definitions mixed into the desktop profile and long shell scripts
embedded in the panel/window-manager configuration. Several scripts also had real
runtime faults that a plain flake evaluation could not detect.

## Confirmed findings and changes

- **Wi-Fi menu sometimes would not open.** Reproduced using the installed script
  against the live scan, with its menu replaced by a cancel-only stub. An SSID's
  punctuation was parsed as signal strength, producing arithmetic and `printf`
  errors before wofi opened. The corrected parser puts unescaped SSID text last,
  validates signal values, and passes the same scan. This follows the
  [nmcli format and connection semantics](https://networkmanager.pages.freedesktop.org/NetworkManager/NetworkManager/nmcli.html).
- **Duplicate/confusing Wi-Fi entries and needless password prompts.** The menu
  exposed N1/N2 implementation keys and repeated names for multiple access points.
  It now displays each name once, hides its keys, and tries saved credentials
  before asking for a password. Names are rendered as plain text.
- **VPN preferences could be overwritten with empty/partial JSON.** The old
  scripts replaced the config even when `jq` failed. They now stop on errors,
  use unique temporary files, and preserve the original on failure. The toggle
  validates configuration before terminating a stuck tray process.
- **OpenCode Blender MCP environment was not applied.** The configuration used
  `env`; the pinned OpenCode runtime reads `environment`. Corrected the key and
  moved settings to Home Manager's native `programs.opencode` module, allowing the
  Blender module to contribute settings directly.
- **Desktop Codex sandbox dependency missing.** Tool execution failed before the
  command started because no `bwrap` was found. The pinned Codex CLI wrapper supplies
  it privately; the desktop wrapper does not. Added `bubblewrap` to the desktop
  user profile. A fresh app process after activation must verify the actual sandbox.
- **Authentication maintenance risk.** sudo and hyprlock replaced complete PAM
  stacks just to change fingerprint ordering. They now use the
  [NixOS PAM rule ordering interface](https://github.com/NixOS/nixpkgs/blob/master/nixos/modules/security/pam.nix)
  to retain password-first/fingerprint-fallback behavior and the standard account,
  session, and final denial rules. Generated stacks were inspected; interactive
  authentication still needs verification after activation.
- **Desktop startup had multiple owners and timing assumptions.** Removed the
  redundant hypridle launch, enabled Waybar's systemd integration, and used the
  Home Manager awww service with a bounded socket-readiness check. Wallpaper
  selection no longer depends on the repository's checkout location or a second
  hard-coded default image. The polkit agent now stops with the graphical session.
- **Configured editor tools were missing.** Conform's automatic package installation
  was disabled while Rust/Zig formatting was configured; rust-analyzer requested
  Clippy without installing it. Enabled formatter installation, added Clippy, and
  updated the manual format binding to the current `lsp_format` setting.
- **Maintenance tooling and documentation were incomplete.** Added a pinned
  development shell, `nix fmt`, ShellCheck and focused behavioral checks within
  `nix flake check`, and a README mapping changes to files and troubleshooting steps.
  Application modules and shell files now have clear ownership. Removed the
  misleading `nuo` alias, which could not advance an exact OpenCode release tag.

## What was retained deliberately

- Both hosts and the existing shared modules, theme, desktop layout, application
  selection, state versions, and input lock file.
- The MT7925 power-saving workaround and current kernel, because the recent driver
  fix is host-specific and there was no evidence supporting a rollback.
- Godot and Blender's prebuilt archives and runtime library fixes. Compiling these
  locally previously exhausted memory. File moves are not a reason to discard them.
- OpenCode's AppImage, Wayland flags, plugin, and skills; its upstream desktop
  derivation has a documented Bun version mismatch.
- Sleev routing was running, configured, and healthy at audit time. It was removed
  from the active configuration on September 23, 2026 at the user's request.
- Browser MIME defaults and application-specific Wayland launchers.

## Remaining limits and follow-up

**The reported connection interruption is not yet attributed.** There was no new
suspend event or MT7925 firmware crash in the inspected logs. The last suspend
ended that morning. The recent event may have involved display blanking rather
than system suspend. Proton logged a server-list refresh failure, and no VPN
interface was present during inspection, but neither observation establishes the
root cause of the app's network loss. NetworkManager was logging only warnings;
normal informational logging is now configured for the next occurrence. No blind
Wi-Fi/VPN restart hook was added.

A later recurrence provided stronger radio evidence and led to a targeted MT7925
single-link workaround. See [the Wi-Fi follow-up](wifi-2026-09-05.md) for measured
latency, the matching upstream regression, and its separate verification status.

**Scar is a deployment template, not a verified server.** Its root UUID remains a
placeholder, and its enabled Minecraft whitelist has no entries. Target hardware,
SSH/account provisioning, and the player list require information from scar.
The audit does not claim scar boots or accepts remote login.

**Mutable application state still matters.** Proton authentication lives outside
Nix. qBittorrent's managed config binds to `proton0`; verify the real VPN device
and be aware that GUI changes to a Home Manager-managed file may cause an
activation conflict. The existing `.backup` policy can also require resolving a
pre-existing backup when an unmanaged file is replaced again. Do not delete or
force-overwrite those files blindly.

**The private goal plugin has a concurrency limit.** Its atomic file replacement
prevents partially written JSON, but it does not coordinate simultaneous CLI and
Desktop processes working on the same project state. A separate lifecycle/concurrency
test effort is appropriate before changing that plugin's persistence design.
Its code was reviewed and syntax-checked; no provider-backed end-to-end goal run
was performed.

**Hardware and interactive behavior require activation.** A build cannot prove
fingerprint authentication, Wi-Fi roaming, sleep/resume, VPN recovery, or a fresh
Wayland login. The running system was not switched during the audit. Two existing
upstream `stdenv.isLinux` deprecation warnings remain; no local code uses that API.

## Validation evidence

- Both NixOS hosts evaluated successfully with `nix flake check`, before and after
  the cleanup. The new script check runs seven isolated regression tests,
  ShellCheck, and a JavaScript syntax check.
- `nix fmt -- --check` passed; hardware configurations and `flake.lock` are unchanged.
- The complete nullrunner Home Manager activation package built successfully.
- Package derivation comparisons preserved all existing application binaries.
  Only Nixvim changed; Bubblewrap was added to the user package list.
- The generated OpenCode JSON matches the installed settings with only the intended
  `env` → `environment` correction. Native module integration also enables the
  existing Stylix target for OpenCode's TUI.
- The generated Hyprland configuration passed `Hyprland --verify-config`.
- An isolated headless Nixvim startup verified the formatter executables and Clippy.
- A harmless Bubblewrap sandbox smoke test succeeded. The desktop application
  still needs a fresh process after activation to inherit the added dependency.
- The fixed menu reached the UI against the same live scan that crashed the
  installed menu. These probes canceled before any connection action.
